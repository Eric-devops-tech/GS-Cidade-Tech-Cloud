COMO USAR
----------
Os comandos Azure CLI abaixo foram escritos para PowerShell no Windows.
Execute uma seção de cada vez e confira a saída antes de continuar.
As linhas iniciadas por # sao comentarios, nao comandos.

ATENCAO
-------
- Este roteiro provisiona recursos Azure que podem gerar custos.
- O ambiente Cidade Tech ja foi provisionado na assinatura Azure for Students.
- Nao repita as etapas 2 a 4 enquanto os recursos deste Resource Group existirem.
- A VM fica ligada e pode consumir creditos enquanto permanecer ativa.
- Informe seu IPv4 público atual na variável $clientIp antes de criar a NSG.
  A regra usa /32 para permitir somente esse endereço; não publique seu IP no Git.
- Não abra a porta 5432 do PostgreSQL nem a porta 22 do SSH para a Internet.
- A VM usa Azure Run Command para administracao, sem SSH publico.
- A API Java e o Dockerfile já estão integrados em api/. Siga as etapas 5 e 6
  para instalar o Docker na VM e implantar a API com o PostgreSQL.
- Nunca coloque senhas reais em comandos, no Git, em capturas de tela ou no vídeo.
- A remoção do Resource Group no final é opcional e destrutiva. Confira o nome
  e faça backup antes de executá-la.

1. LOGIN, ASSINATURA E VARIAVEIS
--------------------------------

az login
az account show --output table

$resourceGroup = "rg-cidade-tech"
$location = "chilecentral"
$vnetName = "vnet-cidade-tech"
$subnetName = "snet-app"
$nsgName = "nsg-cidade-tech"
$publicIpName = "pip-cidade-tech"
$nicName = "nic-cidade-tech"
$vmName = "vm-cidade-tech"
$clientIp = Read-Host "IPv4 público autorizado (somente o endereço, sem /)"
$parsedIp = $null
if (-not [System.Net.IPAddress]::TryParse($clientIp, [ref]$parsedIp) -or
    $parsedIp.AddressFamily -ne [System.Net.Sockets.AddressFamily]::InterNetwork) {
  throw "Informe um endereço IPv4 válido."
}
$allowedIp = "$($parsedIp.IPAddressToString)/32"

--------------------------------

  --name $vnetName `
  --location $location `
  --address-prefixes 10.20.0.0/16 `
  --subnet-name $subnetName `
  --subnet-prefixes 10.20.1.0/24

3. NSG E REGRA DE ENTRADA DA API
--------------------------------

az network nsg create `
  --resource-group $resourceGroup `
  --name $nsgName `
  --location $location

az network nsg rule create `
  --resource-group $resourceGroup `
  --nsg-name $nsgName `
  --name AllowApi8080FromEvaluator `
  --priority 1100 `
  --direction Inbound `
  --access Allow `
  --protocol Tcp `
  --source-address-prefixes $allowedIp `
  --source-port-ranges "*" `
  --destination-address-prefixes "*" `
  --destination-port-ranges 8080

az network vnet subnet update `
  --resource-group $resourceGroup `
  --vnet-name $vnetName `
  --name $subnetName `
  --network-security-group $nsgName

A NSG é aplicada à subnet. A regra de negação padrão bloqueia outras conexões
de entrada. Não crie regras para PostgreSQL 5432 ou SSH 22.

5. INSTALAR DOCKER ENGINE E COMPOSE NA VM
-----------------------------------------
Azure Run Command executa o script Linux abaixo dentro da VM como administrador.
Ele instala o Docker Engine e o plugin oficial Docker Compose.

$bootstrapScript = @'
set -eu
apt-get update
apt-get install -y ca-certificates curl git openssl
install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
chmod a+r /etc/apt/keyrings/docker.asc
. /etc/os-release
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.asc] https://download.docker.com/linux/ubuntu $VERSION_CODENAME stable" > /etc/apt/sources.list.d/docker.list
apt-get update
apt-get install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
systemctl enable --now docker
docker --version
docker compose version
'@

az vm run-command invoke `
  --resource-group $resourceGroup `
  --name $vmName `
  --command-id RunShellScript `
  --scripts $bootstrapScript `
  --output table

6. BAIXAR O PROJETO E INICIAR POSTGRESQL E API
----------------------------------------------
O script cria credenciais aleatórias diretamente na VM, grava o arquivo .env
com permissão restrita e inicializa o gestor. A credencial do gestor fica em
/root/cidade-tech-manager.txt, legível somente por root; ela não é impressa
durante o deploy.

$deployProjectScript = @'
set -eu
if [ ! -d /opt/cidade-tech/.git ]; then
  git clone https://github.com/Eric-devops-tech/GS-Cidade-Tech-Cloud.git /opt/cidade-tech
else
  git -C /opt/cidade-tech pull --ff-only
fi
cd /opt/cidade-tech
if [ ! -s .env ] || ! grep -q '^DB_PASSWORD=.' .env; then
  umask 077
  DB_PASSWORD=$(openssl rand -hex 24)
  JWT_SECRET=$(openssl rand -hex 32)
  printf 'DB_PASSWORD=%s\nJWT_SECRET=%s\nCORS_ORIGINS=http://localhost:8081\n' "$DB_PASSWORD" "$JWT_SECRET" > .env
fi
if [ ! -f .manager-initialized ]; then
  MANAGER_EMAIL=$(sed -n 's/^GESTOR_INICIAL_EMAIL=//p' .env)
  MANAGER_PASSWORD=$(sed -n 's/^GESTOR_INICIAL_SENHA=//p' .env)
  if [ -z "$MANAGER_EMAIL" ] || [ -z "$MANAGER_PASSWORD" ]; then
    MANAGER_EMAIL="gestor@cidade-tech.demo"
    MANAGER_PASSWORD="C$(openssl rand -hex 10)z9"
    sed -i '/^GESTOR_INICIAL_EMAIL=/d; /^GESTOR_INICIAL_SENHA=/d' .env
    printf 'GESTOR_INICIAL_EMAIL=%s\nGESTOR_INICIAL_SENHA=%s\n' "$MANAGER_EMAIL" "$MANAGER_PASSWORD" >> .env
  fi
  umask 077
  printf 'email=%s\npassword=%s\n' "$MANAGER_EMAIL" "$MANAGER_PASSWORD" > /root/cidade-tech-manager.txt
  chmod 600 /root/cidade-tech-manager.txt
fi
chmod 600 .env
docker compose up -d --build --wait --wait-timeout 600
docker compose ps
if [ ! -f .manager-initialized ]; then
  sed -i '/^GESTOR_INICIAL_EMAIL=/d; /^GESTOR_INICIAL_SENHA=/d' .env
  touch .manager-initialized
fi
'@

az vm run-command invoke `
  --resource-group $resourceGroup `
  --name $vmName `
  --command-id RunShellScript `
  --scripts $deployProjectScript `
  --output table

Para consultar a credencial do gestor antes da gravação, execute este comando
em uma sessão privada. A saída contém uma senha; não a compartilhe nem grave:

az vm run-command invoke `
  --resource-group $resourceGroup `
  --name $vmName `
  --command-id RunShellScript `
  --scripts "cat /root/cidade-tech-manager.txt" `
  --query "value[0].message" `
  --output tsv

O volume postgres-data mantém os dados entre reinícios do container. A porta
5432 não é publicada na VM; o banco só é acessível pela rede do Compose.

10. CONSULTA DIRETA AO POSTGRESQL
---------------------------------
O comando executa psql dentro do container do banco. A porta 5432 não é
publicada na VM. Os SELECTs leem dados que a API Java persistiu.

$selectDatabaseScript = @'
set -eu
cd /opt/cidade-tech
docker compose exec -T database psql -U empauta -d empauta -c "SELECT id, titulo, bairro, estado FROM consultas ORDER BY id;"
docker compose exec -T database psql -U empauta -d empauta -c "SELECT consulta_id, usuario_id, escolha FROM votos ORDER BY id;"
'@

az vm run-command invoke `
